### Validated design

`docs/superpowers/specs/2026-05-02-local-cache-design.md`. Resolved decisions:

- Scope tier C — durable archive (rows never DROPped; gone-from-source is a flag, not a delete).
- Cached fields tier A — metadata only; transcript text not cached.
- Sync engine tier B — incremental every 6 h + full reconciliation weekly at 03:00 local.
- Bootstrap UX tier B — soft block + persistent progress banner.
- Single unified `meetings` table with `state` (op_state) and `source_state` (live/gone) axes.

### Deviations encountered (worth knowing)

- Phase 1 Task 3: plan's migration ordering had a real bug — `CREATE INDEX IF NOT EXISTS` validates the column even with `IF NOT EXISTS`, so it failed on legacy DBs. Agent fixed by running migration *before* `executescript` with a fresh-DB guard.
- Phase 1 Task 1: pre-existing `tests/core/test_models.py::test_meeting_state_values` hard-coded the enum value set; needed a one-line update.
- Phase 2 Task 4: plan's `ControllableMeetingRepository` had a dead `page_size` parameter — agent added `effective_limit = min(limit, page_size)`.
- Phase 2 Task 10: dropped `# noqa: BLE001` from sample (CLAUDE.md forbids), parked `asyncio.create_task(...)` on `app.state.sync_scheduler_task` for RUF006.
- Phase 3 Task 3: 5 existing CLI tests construct `_common.Deps(...)` directly without `scan_repo`; added `__post_init__` to `Deps` so it defaults to `client` (later flipped to `ManifestBackedRepository(manifest)` in Phase 6).
- Phase 3 Task 4: cleanup factory is `_service` (not `_scan_service` as the plan says).
- Phase 4 Task 2: `POST /sync/now` parses body as form (not query params), to match what tests send. 409-test seeds the lock via `client.portal.call(lock.acquire)` to avoid TestClient deadlock.
- Phase 4 Task 6: banner partial restructured so idle-with-failure and idle-no-history are reachable (the plan's `{% elif %}` chain on `last_run.outcome` was unreachable when `state="running"` was false but no `last_run` existed).
- Phase 5 Task 2: dropped redundant 6th `meetings_seen` arg from `snapshot_callback` signature; kept the 5 distinct values. Wrapped callback in `contextlib.suppress(Exception)` so a buggy publisher cannot abort an in-flight sync.
- Phase 5 Task 5+6: implemented in opposite order — e2e test needed `list_meetings_page` from Task 6.
- **Phase 6 Task 4 (added during recovery): Pipeline didn't handle `MeetingState.KNOWN`.** After the read-path flip, the cache adapter pre-seeds rows in KNOWN state, but `Pipeline._process_one` and `Pipeline.archive_one` only matched None/PENDING/failed_*, so they silently fell through and skipped archive+delete on cached meetings. Fix: KNOWN now transitions to PENDING and archives, identical to failed_* recovery. Existing `_VALID_TRANSITIONS` already permitted KNOWN→PENDING. Plus updated 8 test fixtures to seed `manifest.upsert_known(...)` alongside their in-memory client seed.
