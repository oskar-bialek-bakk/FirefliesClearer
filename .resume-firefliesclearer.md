## Phase 6 known issue — ⚠️ OR/AND semantic shift in migrated presets

v1 `run` used **OR** semantics: a meeting matched if it was `older_than_days` **OR** had `no_transcript` (when `delete_failed_transcripts=true`). v2 `ScanService.scan()` uses **AND** semantics: all active filters in a single preset must match.

Task 6.3's migration produces a **single** preset called "Auto cleanup" with both `older_than_days` and `no_transcript=True` set — under AND, this is **strictly narrower** than v1 OR. A migrated v1 user running `firefliesclearer run --apply` will see **fewer matches** than before. Spec § 7.1 example explicitly shows this single-preset shape, so the implementation matches the spec — but the spec itself contains the contradiction (the description says "Old meetings AND anything without a transcript", which is OR in plain English but AND in code).

**Recommended remediation (deferred — not blocking Phase 6):**
- Either: split migration into TWO presets (deviates from spec § 7.1).
- Or: add a release-note callout instructing users to split the migrated preset into "Old meetings" + "No transcript" presets if they want the v1 OR behavior.
- Or: leave as-is and mention in CHANGELOG (Phase 9.5).

I lean toward release-note + CHANGELOG entry — the AND model is more intuitive and matches the wizard's behavior; users who want OR can create two presets.

## Plan-vs-reality deviations (already-known traps)

These bit Phase 4-6 implementers; project memory `project_firefliesclearer.md` has the full list. Highlights:

- **`Pipeline.archive_one(meeting)` / `purge_one(meeting)`** take a `Meeting` object, not meeting_id.
- **`Manifest.open(path)` not `Manifest(path)`**; `Manifest.transition(mid, *, to=, at=, ...)` keyword-only on `to`/`at`.
- **Modern Starlette `TemplateResponse(request, "name.html", {ctx})`** — plan's old form raises TypeError.
- **`asyncio_mode = "auto"`** in pytest — never add `@pytest.mark.asyncio`.
- **Project ruff selects `["E","F","W","I","N","UP","B","SIM","RUF"]`** but NOT `SLF001`/`BLE001` — don't add those noqa directives.
- **CSRF middleware urlencoded-only**, double-submit cookie pattern; HTMX POSTs include `_csrf` via `<input type="hidden">` or `hx-include="[name='_csrf']"`.
- **Tests for web routes use raw `sqlite3.connect(check_same_thread=False)`** in `tests/web/conftest.py:configured_app`.
- **TestClient context-manager + `client.portal.call(...)` pattern** required for async ops (see `tests/web/routes/test_cleanup_step3.py:27-42`).
- **mypy class-scope name resolution gotcha (Phase 6.2):** `class Foo: def list(self) -> list[Bar]: ...` fails mypy even with `from __future__ import annotations` because mypy resolves names against class scope, not module scope (PEP 563 only defers RUNTIME evaluation). Workaround in `preset_service.py`: `_List = builtins.list` alias used in internal `list[X]` annotations.
